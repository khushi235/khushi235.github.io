Changing text on your site

Everything a visitor reads lives in Markdown files. You can edit them straight on GitHub.com — no laptop, no terminal, no code. This sheet covers what to click, what to type, and the handful of rules that keep the site from breaking.

The short answer

Yes. Edit a file on github.com, click Commit changes, and the site rebuilds and republishes itself automatically. Your edit is live at khushi235.github.io in about a minute. You do not need to run anything.

One exception: replacing the resume PDF needs a laptop (see section 8). Everything else on this sheet is pure point-and-click.

01What happens when you save

  1. YOUEdit & commitChange text in a .md file on github.com.
  2. AUTOChecks runContent is validated and type-checked.
  3. AUTOSite rebuildsPages are regenerated from your text.
  4. AUTOLivePublished to khushi235.github.io, ~1 min.

The safety net matters: if your edit has a mistake, the build stops and the live site stays exactly as it was. A broken edit can never take your site down — it just doesn't publish. You'll see a red ✗ in the Actions tab telling you which file and which field to fix.

03The click-by-click routine

  1. Go to github.com/khushi235/khushi235.github.io.
  2. Click through the folders to the file you want — e.g. src → content → projects → diamond-pricing-ai.md.
  3. Click the pencil icon (top right of the file) to edit.
  4. Change only the words. Leave every field name, colon, dash and indent exactly as it is.
  5. Click Commit changes…, type a short note like "Update diamond project results", keep Commit directly to the main branch selected, and confirm.
  6. Open the Actions tab. Wait for the green ✓ (about a minute).
  7. Open khushi235.github.io and hard-refresh: Ctrl+Shift+R.
Editing on your phone

Same steps in a mobile browser. If GitHub shows you the rendered view instead of the editor, tap the ⋯ menu → Edit. Requesting the desktop site makes the pencil icon easier to find.

04How these files are laid out

Every content file has two parts. The bit between the two --- lines is structured data (fields the site reads). Everything below the second --- is free prose — write whatever you like there. 

--- <- structured fields start here
title: Diamond Pricing AI
tagline: Defensible Prices and Real Comparables
order: 4
technologies:
  - Python
  - SQL
--- <- structured fields end here

Write normal sentences down here. **Bold** and *italic* work.
Blank line between paragraphs.

The five rules that prevent every common breakage

  1. Never rename the words before a colon. title:, order:, summary: are wiring, not labels.
  2. Spaces only, never Tab. Keep the existing indentation — copy the line above and edit it.
  3. A list item is a dash, a space, then the text. - Python, never -Python.
  4. If your text contains a colon-space or starts with a quote, wrap the whole line in double quotes, or use the >- block style below.
  5. Leave >- blocks alone structurally. Just retype the sentences under it, keeping them indented.

✓ Safe

tagline: Faster, cleaner reporting
description: >-
  A long paragraph that can
  wrap across several lines
  as long as each one stays
  indented by two spaces.
role: "Analyst: Data & AI"

✗ Breaks the build

Tagline: Faster reporting
role: Analyst: Data & AI
technologies:
-Python
description: >-
Not indented, so YAML
loses track of the block.

05Recipes

Change your headline, bio or the four big numbers

All in src/content/profile/profile.md:

role: Data & AI Analyst            # under your name in the hero
headline: I turn messy data into…   # the big statement line
availability: Open to data roles   # delete this line to hide the pill
metrics:                          # max 4 — a 5th fails the build
  - value: 40%
    label: Fewer analytical errors after automation

The paragraphs below the closing --- are your "about" text. Rewrite them freely.

Edit an existing project

Open src/content/projects/<name>.md. The fields you'll most likely touch: title, tagline, description (the card summary), problem, approach, architecture (bullet list), decisions (title + detail pairs) and outcomes (value + label pairs). Anything optional you delete simply stops appearing.

order controls position — lower numbers come first. featured: true promotes it to a full-width case study. status must be one of active, shipped, archived. theme must be one of meadow, golden, sand, slate.

Add a new project

  1. Open src/content/projects/_template.md and copy everything.
  2. In the projects folder click Add file → Create new file.
  3. Name it my-new-project.md — lowercase, hyphens, no spaces. The filename becomes the web address: /fetch/my-new-project/.
  4. Paste the template, fill it in, delete the commented-out lines you don't need, commit.

The card appears on the homepage and the detail page builds itself. Nothing else to update.

Remove a project

Open the file → ⋯ menu → Delete file → commit. Keep at least one project; an empty folder fails the build.

Add or edit a job

src/content/experience/<name>.md. Dates are YYYY-MM (e.g. 2025-04). For your current role, use current: true and leave end out — it displays as "Present". order: 1 is the newest role.

Skills

src/content/skills/<name>.md. Items can be a plain string, or a string with extra detail: 

items:
  - Power BI
  - name: SQL
    note: Primary language day to day
    core: true          # renders brighter

Social links

The socials: list in profile.md feeds the nav, the contact section, the footer and the search-engine data all at once. Change it in that one place.

06What you must not touch

Leave these alone
  • src/styles/ — controls how everything looks.
  • src/layouts/, src/lib/, src/scripts/ — plumbing.
  • astro.config.mjs, package.json, package-lock.json, tsconfig.json.
  • .github/workflows/deploy.yml — the thing that publishes the site.
  • src/content.config.ts — the rulebook your content is checked against.
  • Anything inside < > angle brackets, or any class="…" value.

07Section headings and intro lines

The five section names (Origin, Trail, Fetch, Pack, Whistle) and their intro lines are not in Markdown — they're in component files. Editing them is still safe, but be surgical: change only the words between the quote marks, and keep both quotes. 

// src/components/Fetch.astro
  title="Fetch"
  lede="Things I went and got: analytics systems built end to end."
  • Intro lines: Trail.astro, Fetch.astro, Pack.astro (look for lede=).
  • Contact paragraph: Whistle.astro (plain sentence inside <p> tags).
  • The nav's section names also live in src/lib/site.ts — if you rename a section, change it in both places.
  • 404 wording: src/pages/404.astro.
  • Footer photo credit: src/components/Footer.astro.

If a word you type contains a double quote, use an apostrophe instead — it's not worth the risk.

08Replacing the resume

This one is not a web edit

Never upload your personal resume PDF straight into the repo. The copy you email people has your phone number in the header. Anything in public/ is downloaded, indexed and scraped — you cannot take it back.

On a laptop with the project cloned:

  1. Save your new full resume at the project root as Khushi Shukla Resume.pdf. That name is ignored by Git, so it never gets published.
  2. Run npm run resume. It strips the phone number out of the PDF properly, rebuilds the preview images the on-site viewer shows, and refuses to finish if a phone number survives.
  3. In src/content/profile/profile.md, update resume.updated to the new month (e.g. 2026-11).
  4. Run npm run verify, then commit and push.

Needs Python with PyMuPDF once: pip install pymupdf.

Changing only the date shown next to the resume — with no new PDF — is a normal web edit: just change resume.updated in profile.md.

09Checking it worked, and undoing it

Did it publish?

  1. Actions tab → newest run at the top.
  2. Green ✓ = live. Yellow dot = still building, wait. Red ✗ = not published, site unchanged.
  3. On a red ✗, click the run → the failed step → the last red lines name the file and field to fix. Fix it and commit again.

Still seeing the old text?

That's your browser cache, not the site. Hard-refresh with Ctrl+Shift+R (⌘+Shift+R on Mac), or open it in a private window.

Undo an edit

  1. Commits list → click the commit you regret.
  2. Revert → confirm.
  3. The previous wording redeploys on its own in about a minute.

Nothing is ever lost — every version of every sentence is in the history.

10One-minute summary

  • Words live in src/content/. Edit them on github.com and commit to main.
  • Publishing is automatic. Roughly one minute. No commands to run.
  • Change words, never field names, indentation or punctuation structure.
  • A bad edit cannot break the live site — it just refuses to publish.
  • New project = new .md file copied from _template.md.
  • New resume PDF is the only task that needs a laptop.
  • Hard-refresh before believing the site didn't update.
